# Юридические документы

Здесь лежат исходники оферты и политики в том виде, в каком они публикуются.
Репозиторий — источник правды: опубликованная страница должна совпадать с
файлом отсюда, а правки идут сначала сюда.

Таблиц в текстах нет намеренно: telegra.ph их не поддерживает, и перечни
сроков хранения и тарифов оформлены списками. Так опубликованное совпадает с
файлом слово в слово.

## Как публиковать

telegra.ph не понимает markdown при вставке: решётки и звёздочки останутся
в тексте как есть. Зато он понимает форматированный текст из буфера обмена.
Поэтому документы сначала превращаются в HTML:

```bash
python scripts/legal_to_html.py   # → docs/legal/html/*.html
```

Файл открывается в браузере, выделяется целиком, копируется и вставляется в
редактор telegra.ph. Заголовки, списки и полужирный переносятся сами.

## Порядок публикации

Ссылки в документах взаимные, поэтому публикуется в два прохода.

1. Опубликовать оба документа на telegra.ph как есть — адреса появятся сразу.
   **Сделано.**
2. Подставить в текст полученные адреса, дату и аккаунт поддержки.
   **Сделано, кроме аккаунта поддержки.**
3. Перезалить обе страницы через Edit.
4. Прописать в Railway `OFFER_URL`, `PRIVACY_URL` и `DOCS_VERSION`.

До шага 4 бот оплату не показывает: вместо неё экран «оплата скоро». Это
осознанно — брать деньги, не показав условия, нельзя.

**Право правки на telegra.ph хранится в браузере.** Если почистить куки или
открыть страницу с другого устройства, кнопки «Edit» не будет. Чтобы этого не
случилось, сразу после публикации привяжите страницы к аккаунту Telegram
через бота `@telegraph` — тогда правка доступна с любого устройства.

## Про версию документов

`DOCS_VERSION` — строка вида `2026-08-31`, совпадающая с датой редакции в
самих документах. Она записывается в каждый заказ и в лог согласия, поэтому
менять её нужно при каждой правке текстов: иначе по записи «согласился с
редакцией такой-то» нельзя будет понять, с чем именно.
